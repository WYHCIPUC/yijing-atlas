5. 先复现或补关键测试，再实施最小修改；运行相关检查并记录真实结果。
6. 检查最终 diff，更新任务状态、证据和交接。未跑、失败和外部阻塞必须保留。

禁止重置、覆盖或遗漏当前未提交修改；禁止擅自引入 React、构建系统、账号或业务后端；禁止为了显示入口而绕过六家注疏门禁。当前静态主应用不包括归档 Flutter，也不包括宣传视频工程的 React 运行环境。

## 2. 权威顺序与版本解释

### 2.1 需求、现状和证据不是同一个维度

| 维度 | 状态 | 判定方式 |
| --- | --- | --- |
| 需求 | 已确认 / 建议改进 / 未来独立方案 | 用户确认与设计/领域决策；建议不能伪装为原始需求 |
| 实现 | 已实现 / 部分实现 / 未实现 / 受门禁阻塞 | 代码和真实入口；有引擎不代表有完整用户流程 |
| 验证 | 本轮验证 / 历史验证 / 验证失败 / 未验证 | 带日期、版本、环境与范围的实际记录 |
| 发现依据 | 代码已确认 / 行为已复现 / 待验证假设 | 静态差异、可重复行为和风险推断必须分开 |

“已实现”不能自动推导“本轮验证通过”。本册所谓“当前”指本地源码快照，不指线上生产版本。

### 2.2 冲突裁决

1. 用户最新明确要求优先。
2. [UI 设计基线](UI-DESIGN-BASELINE.md) 负责已确认的视觉、交互和信息架构。
3. 领域 PRD 负责算法、内容、数据与评分规则；发生业务语义冲突先记录差异，不能任意改算法。
4. 本册和专题负责当前事实、差距、建设默认、任务与证据；历史文档保留为历史。
5. 代码用于证明现状，不用于把尚未实现的已确认要求自动取消。

已裁决的典型差异：

- 学习一级入口采用“今日修习、五阶学程、典籍书库、修习谱”；旧学程/考评/资料/数据入口映射到新结构。
- 占筮学习采用“引导解卦、自主解卦、直接研读”三路径；当前五个自评勾选不等于五步客观挑战。
- 欢迎页今日一卦/分享深链进入深读；黄历未来“项目今日一卦”入口按已确认基线聚焦，不能统一改成同一路径。
- 黄历早期音色描述须服从后续音效批准/弃用清单；不得重新启用已弃用素材。
- 手机保证核心流程；独立六家注疏实验室仍有桌面与内容门禁，不等于每项桌面能力均已手机化。

## 3. 项目定位与边界

易象图谱是传统文化学习与自我反思工具，围绕“观象—研读—主动回忆—间隔复习—表达—考评—实践”建立学习闭环。它不对现实预测是否应验评分，不替代医疗、法律、投资等专业判断。

当前主应用为本地优先静态站点：HTML/CSS/ES Modules + Canvas + 本地 Three.js/GSAP/Lenis/D3；没有前端构建步骤，正常浏览不要求安装 npm 包。仓库实际存在开发和打包依赖，不能称“完全没有第三方依赖”。

### 3.1 前端、服务和后端

| 层 | 当前职责 | 不应误认为 |
| --- | --- | --- |
| 网页 | 交互、渲染、纯逻辑、浏览器本地数据、公开 JSON | 账号平台或云端数据库 |
| npm start | Node 静态文件 HTTP + gzip，默认本机 3030 | 业务 API 服务 |
| Windows SEA | 内嵌资源、启动本地服务器、打开浏览器 | 原生桌面 UI 或云同步客户端 |
| 数据工具 | 本地生成/修订 JSON、结构校验 | 在线管理后台 |
| 可选复讲客户端 | 用户主动请求同源评阅服务，失败用本地自评 | 仓库已经提供智能后端 |
| 宣传工程 | 独立 Remotion/React/TypeScript 视频素材与成片 | 网页架构依赖 |

账号、多端同步、远程笔记、管理后台、数据库、计费和社交均为未来独立立项；不因当前不存在就视为本轮缺陷。

### 3.2 不可擅改的不变量

- 六位卦码自下而上；0 阴 1 阳，前 3 位为下卦、后 3 位为上卦。
- 六爻正文初至上；SVG/Canvas 卦象仍初爻在下。
- 错、综、互、指定动爻的变卦规则保留。
- 黄历使用 Asia/Shanghai 民用日，春节换农历年、立春换干支年、十二节换月、午夜换日；范围 1900—2199 不能冒充全范围权威认证。
- 课程保持开放，不用掌握度、学阶或成就锁住核心知识。
- 聚焦和快读不计正式深读；正式阅读和成就沿用稳定幂等规则。
- 私人文本默认不外发；明确保存的笔记与备份仍是私人文件。
- 原典、易传、注疏、项目导读、象数、术数、历法、民俗分层；待校验标签不隐藏。
- 六家内容只有完整来源、适用锚点、底本和双校证据通过，才可另行开启发布门禁。

## 6. 建设顺序和完成定义

任务顺序以 [执行卡](development/12-ai-execution-tasks.md) 的依赖为准：

1. 复现并定位浏览器验收失败；核对学习证据与保存副作用。
2. 完成学习、阅读、占筮、关系的跨模块闭环。
3. 落实黄历、修习谱、统一反馈和声音语义等已确认业务细节。
4. 按原卡需求性质、采纳状态与依赖推进数据韧性、离线、统一组件、资产许可与长期容量；建议项不自动成为必做。
5. 持续完成原典/注疏校勘；补设备、读屏、真实缩放、性能和当前 Windows 证据。
6. 用户另行要求发布后，才执行远程发布与生产复验。

一项任务只有实现目标、关键回归、真实交互（适用时）、diff、文档和证据均满足才可标完成。需要外部证据时写明“受阻原因、已完成部分、缺少的具体输入”；不以预算或时间不足将其标为通过。
