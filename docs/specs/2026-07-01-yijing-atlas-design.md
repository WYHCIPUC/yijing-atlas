## 0. 设计动机：为什么要重构

原有设计是一个**功能齐全但形态平庸**的易学工具站——7 个并列 Tab（查阅/八卦/学习/黄历/复习/测验/占筮），每个 Tab 各管各的。它能用，但和市面上几十个易学 App 没有本质区别：**一次只给你一个卦，从不让你看见卦与卦之间的关系**。

而《易经》的"易"字，核心就是**变**。64 卦不是 64 个孤立条目，而是一张关系网——每个卦都连着它的错卦（阴阳全换）、综卦（视角倒转）、互卦（内藏之卦）、变卦（爻动之变）。这套关系恰恰是 64 卦体系最深的结构之美。

本项目原有设计里有一个被埋没的工程内核：**6 位二进制串作卦的主键**（自下而上，阳 1 阴 0）。它让错/综/互/变全部退化为一行位运算（取反、翻转、切片）。这个内核天生就是为"关系网"准备的，却只被用在占筮查表这种边缘场景。

**易象图谱**把这个内核提到产品灵魂的位置：整个产品的入口和主场是一张**可探索的 64 卦关系星图**，用户在星图中漫游，亲眼看见卦如何"变"，从而理解《易经》作为系统的真貌。复习、测验、占筮、黄历不再是并列 Tab，而是**长在星图上的状态层**。

这是别的易学产品做不到的——因为它们没有 binaryCode 主键 + 位运算这套工程地基。我们有了，所以能做到。

## 1. 目标与成功标准

### 1.1 目标

打造一个以**卦象关系图谱**为灵魂的易学产品。用户打开即见一张可漫游的 64 卦星图，在星图中探索卦如何变化、阅读经文、复习记忆、占筮起卦、查看黄历——所有功能统一在图谱这个主场里，而非分裂的页面。

### 1.2 成功标准

- 首屏即一张可拖拽、缩放、自转的 64 卦力导向星图，视觉震撼
- 悬停任意卦，其错/综/互/变四条关系立即点亮连线
- 点击进入卦象详情，长卷阅读经文 + 中段插入"它如何变"
- 64 卦经文内容完整（公版原文 + 自撰白话注解）
- 复习/测验/占筮/黄历四模块均以"星图状态层 + 右侧抽屉"形态工作，不离开星图主场
- 整体配色统一（墨空鎏金），模块状态用金色浓淡区分而非四种跳跃色
- 桌面浏览器优先，界面元素与字号适配大屏阅读

### 1.3 非目标（YAGNI）

- 不做账号体系与云端同步（纯本地 localStorage）
- 不做社区/分享/社交功能
- 不做付费/内购
- 不做服务器后端（纯静态，可部署 GitHub Pages）
- 不做命理八字排盘（超出范围）
- 不做实时天象（日出日落、月相图）

## 2. 核心理念：图谱为体，模块为用

### 2.1 统一规律

整个产品只有**一个全局视图**——星图。所有功能模块都遵循同一形态：

```
每个模块 = 星图上的一种「状态层」+ 点开后「右侧滑出抽屉」
```

- **状态层**：模块在星图上用视觉标记表示（呼吸闪烁、高亮、连线等），用户一眼看到"哪些卦和这个模块有关"
- **抽屉**：重交互内容（复习卡片、测验题目、占筮解读、黄历详情）在右侧滑出面板展开，不挤进星图

用户始终在星图这个主场里，通过顶部的**模式切换器**（探索 / 复习 / 测验 / 占筮 / 黄历）切换的是星图的状态层，而非跳转到独立页面。

### 2.2 模式切换器（非传统 Tab）

顶部不再是 5 个并列 Tab，而是一个**模式切换器**：

| 模式 | 星图状态层 | 抽屉内容 |
|---|---|---|
| **探索**（默认） | 无特殊标记，纯净星图 | 无（或卦象详情，点击星进入） |
| **复习** | 待复习的卦**呼吸闪烁**（金色脉冲） | 翻转卡片复习（正面提示→背面原文） |
| **测验** | 出题：中心卦高亮，候选卦可点选 | 题目 + 答题反馈 |
| **占筮** | 起卦后本卦+变卦**高亮连线**（虚线） | 本卦→变卦解读 |
| **黄历** | 今日卦**金色虚圈标注** | 农历/干支/节气/宜忌/今日卦解读 |

切换模式时，星图本身不消失，只是叠加/切换不同的状态视觉层。这保证了产品体验的连续性和统一感。

### 2.3 颜色编码（墨空鎏金）

不使用四种跳跃的颜色（红/绿/蓝/橙）区分模块，而是用**金色的深浅浓淡**：

```
深空墨蓝底：#0a0e1a
羊皮卷（抽屉/详情）：#e8d9b8 上的深色文字
主金色（探索/连线/卦象）：#c9a96a

模块状态色（金色浓淡）：
  复习 —— 亮金脉冲 #e8d09a
  测验 —— 主金 #c9a96a
  占筮 —— 浅金连线 #d4bc8a
  黄历 —— 深金虚圈 #a08850
```

像夜空中的星辰只有一种色温。克制、统一、高级。

## 3. 星图：产品的主场

### 3.1 布局：力导向（关系涌现）

64 颗星（卦）在画布上通过**力导向物理模拟**自动排布：

- 每两颗星之间存在**斥力**（防止重叠）
- 有关系的星之间存在**引力**（错/综/互/变关系越密，距离越近）
- 系统达到力学平衡后，关系密集的卦自然聚拢成星团

**涌现效果**：泰与否互为错综，会紧紧相邻；乾（111111）与坤（000000）作为互为错卦的两极，会形成对称结构；自为综的卦（如坎）会有独特的自环特征。这些结构之美由数据自动涌现，不需人工排布。

**技术选型**：项目不强制零依赖。力导向模拟优先采用**成熟轻量库**（如 d3-force，约 30KB），其力学模型（n-body 斥力 + 弹簧引力 + 阻尼）经过广泛验证，调参成本低、布局稳定。若评估后认为 d3-force 的迭代性能在低端设备不足，可降级为**预计算静态布局**（构建期跑一次模拟，导出坐标 JSON，运行时直接渲染，拖拽时不重新平衡）。

### 3.2 交互状态

**默认态 · 静默的宇宙**
- 64 颗星缓慢自转（每分钟一圈），星点有微弱的明暗呼吸
- 所有星暗淡，关系连线几乎不可见
- 整体如真实星空，沉静

**悬停态 · 点亮一颗星**
- 悬停的星放大 + 发光（金色光晕）
- 它的**四条变卦**（错/综/互/变）同时被点亮，连出实线
- 连线旁标注关系名（错/综/互/变）
- 其余星和线退到背景（降低不透明度）
- 一眼看清"这颗星连着谁"

**点击 · 进入详情**
- 点击星 → 进入该卦的详情页（长卷阅读式，见 §4）

**操作汇总**

| 操作 | 效果 |
|---|---|
| 拖拽空白 | 旋转整个星图，换个角度看宇宙 |
| 滚轮 / 双指 | 缩放，拉近看局部，拉远看全局 |
| 悬停星 | 点亮它的四条变卦（预览关系，不离开星图） |
| 点击星 | 进入该卦详情页 |
| 搜索框 | 输卦名直接定位，找到那颗星并高亮 |
| 右下按钮 | 切换连线层：只看错卦网 / 只看综卦网 / 全部 / 隐藏 |
| 顶部模式切换器 | 切换星图状态层（探索/复习/测验/占筮/黄历） |

### 3.3 星的视觉

每颗星用一个小圆点表示，悬停或选中时旁边浮现该卦的**简化卦象**（SVG 六爻图）+ 卦名。星的大小可按"关系密度"（连出的边数）微调——关系越密集的卦越大越亮，形成视觉重心。

## 4. 卦象详情页（长卷阅读式）

用户点击星进入。采用**单栏向下滚动**的长卷结构，经文为主、关系为辅。

### 4.1 结构（自上而下）

```
┌─────────────────────────────────────┐
│  [SVG 六爻图 · 大尺寸]               │  卦象可视化
│  泰 · 天地在下交                     │  卦名 + 副标题（自撰一句话点睛）
│  第11卦 · 111000 · 下乾上坤          │  卦序 + binaryCode + 上下卦
├─────────────────────────────────────┤
│  卦辞                                │  公版原文
│  [自撰白话注解]                      │  AI 撰写的简明解读
│                                      │
│  彖传                                │  公版原文 + 注解
│  大象传                              │  公版原文 + 注解
├─────────────────────────────────────┤
│  ▼ 它如何变（中段插入·chip 标签）     │  关系区：轻量展示
│  [错→否] [综→否] [互→归妹] [变→升…]  │  每条可点击跳转
├─────────────────────────────────────┤
│  初九：爻辞原文                      │  六爻（自上而下展示）
│    [小象传]                          │
│    [自撰白话注解]                    │
│  九二 ……                            │
│  （六爻逐条）                        │
├─────────────────────────────────────┤
│  用九 / 用六（仅乾坤）               │
│  序卦传                              │  该卦在卦序中的逻辑
└─────────────────────────────────────┘
```

### 4.2 排版要求

- **桌面优先**：内容区最大宽度约 760–820px 居中，留白充足
- **大字号**：正文 17–18px，标题 22–28px，卦名 32px+，行高 1.8，适配长时间阅读
- **经文与注解视觉分层**：公版原文用稍大/加重/主金色标注，自撰白话注解用次级色（灰色调）缩进展示，一眼区分"原文"与"解读"
- **关系区**："它如何变"用 chip 标签轻量插入中段，不喧宾夺主；点击任一 chip 跳转到对应卦的详情页
- **移动端**：单栏自适应，字号略缩但保持可读

## 5. 内容策略

### 5.1 数据来源与版权

- **公版原文**：卦辞、爻辞、彖传、大象传、小象传、序卦传、用九/用六——采用十三经注疏本底本（公版古籍，无版权限制）
- **白话注解**：由 AI 参考孙振声《白话易经》等著作的**解读框架和教学视角**，**用自己的话独立撰写**简明注解，**不照抄任何受版权保护的原文文字**
- 可在项目说明中注明"白话注解参考孙振声《白话易经》等著作的解读思路"

### 5.2 64 卦经文补齐

现有数据仅 9 卦（乾、坤、屯、蒙、需、讼、师、比、泰）有完整经文，其余 55 卦为空骨架。补齐策略：

- AI 一次性补齐至 64/64，严格遵循现有 9 卦的 JSON 结构格式（`fill_text.dart` 为格式范本）
- 补齐后用 `data-loader.js` 的启动自检校验：64 卦 binaryCode 唯一、卦序 1–64 连续、binaryCode 与 lines 爻象一致
- 任何录入错误在加载期即暴露

### 5.3 数据结构（沿用原有设计）

`hexagrams.json` 单卦结构不变（见原设计文档 §3.1），增加可选字段：

```json
{
  "number": 11,
  "name": "泰",
  "fullName": "地天泰",
  "binaryCode": "111000",
  "trigramLower": "qian",
  "trigramUpper": "kun",
  "judgement": "泰：小往大来，吉，亨。",
  "judgementNote": "（自撰白话注解）",
  "image": "天地交，泰；后以财成天地之道……",
  "imageNote": "（自撰白话注解）",
  "tuan": "泰，小往大来，吉亨……",
  "lines": [
    { "position": 1, "isYang": true, "text": "初九：拔茅茹……", "xiang": "……", "note": "（自撰白话注解）" }
  ],
  "orderRemark": "履而泰然后安……"
}
```

新增 `*Note` 字段承载自撰白话注解。无注解的条目该字段为空字符串（优雅降级）。

## 6. 模块设计（长在星图上的四层状态）

### 6.1 复习模块

**星图状态层**：今日待复习的卦呈现**金色呼吸脉冲**（亮金 #e8d09a，带扩散光晕），用户一眼看到今天该复习哪几颗星。无待复习的卦则星图纯净。

**抽屉交互**：
- 点击待复习的星 → 右侧滑出复习抽屉
- 翻转卡片：正面显示提示（如"第 11 卦，下乾上坤"），背面显示原文（卦辞/爻辞）
- 自评三档："忘了 / 模糊 / 记得"，按 SM-2 简化版间隔算法（1/2/4/7/15 天）安排下次复习
- 复习完一颗，该星的脉冲消失

**数据**：复用原有 review-engine 设计（SM-2 算法），复习卡片来源 = 64 卦经文 + 黄历术语。进度存 localStorage。

### 6.2 测验模块

**星图状态层**：进入测验模式后，星图变为**答题画布**——中心高亮一个卦（题目），其余相关的卦变为可点选的候选。

**抽屉交互**：
- 题目在抽屉显示，如"泰卦的**错卦**（阴阳全换）是星图上的哪一颗？"
- 用户直接在星图上点击认为正确的星
- 答对 → 连线亮起 + 简短反馈；答错 → 正确答案高亮 + 显示解析
- 题型：错卦辨识、综卦辨识、卦象→卦名、卦名→卦象、爻辞填空
- 智能出题：优先考掌握差的、最近复习过的；错题自动进复习队列

**价值**：在星图上答题比看文字选项更直观，顺便强化对星图空间结构的记忆。

### 6.3 占筮模块

**星图状态层**：起卦（金钱卦/大衍筮法/梅花易数）完成后，星图上**本卦与变卦高亮**（浅金 #d4bc8a），之间用**虚线连接**并标注变爻位置。直观看见"从哪个卦变成了哪个卦"。

**抽屉交互**：
- 显示起卦方法、得卦过程
- 按变爻规则（0/1/多个变爻）取对应卦辞或爻辞为断
- 本卦→变卦的解读，含公版原文 + 自撰注解
- 历史占卦记录可回看（存 localStorage）

### 6.4 黄历模块

**星图状态层**：黄历推算出的"今日卦"在星图上用**深金虚圈**（#a08850）标注，把日常时间线和卦的宇宙联系起来。

**抽屉交互**：
- 以当天日期为默认切入：农历日期、年/月/日干支、生肖、纳音、节气、建除值位、二十八宿、彭祖百忌、宜忌事项
- 每个术语可点击查义（结构化解读）
- "今日解读"区把当日术语串联成连贯讲解
- 日期可切换（左右箭头/日期选择器）

**算法**：沿用原黄历设计（寿星天文历：VSOP87 太阳黄经 + ELP2000 月亮黄经 + 定朔定气 + 干支 + 择日）。精度目标：节气误差 <2 分钟，农历与紫金山天文台历书一致。

> **注意**：原 plan 中黄历算法存在 4 处已知缺陷（见原项目梳理），实施时需修复：
> 1. 天文算法 UT 方向偏差（~5.6h）
> 2. 农历闰月判定（`monthHasZhongQi` 永远返回 true）
> 3. 干支基准 `DAY_GZ_BASE_IDX` 自相矛盾
> 4. `selection.js` 的 `toJDUT` 占位符

## 7. 技术架构

### 7.1 技术栈立场

**务实优先于纯洁性，但避免过度工程化。** 不强制零依赖，可引入成熟轻量库解决具体问题；但不引入重框架（React/Vue 等），保持纯静态网站的本质。

| 层面 | 选型 | 理由 |
|---|---|---|
| 渲染 | Canvas 2D（星图）+ DOM/SVG（详情/抽屉） | 星图节点多需高性能渲染用 Canvas；详情页文字用 DOM 利于排版 |
| 力导向 | d3-force（~30KB）或等价轻量库 | 成熟稳定的 n-body 物理模拟，调参成本低 |
| 路由 | 原生 hash 路由 | 无需框架 |
| 状态管理 | 原生 JS（模块单例） | 无需框架 |
| 数据 | JSON 文件 + fetch | 原有方案 |
| 用户进度 | localStorage | 原有方案 |
| 构建 | 零构建链（ES Modules 直接加载）或极简打包 | 保持部署简单 |

### 7.2 目录结构

```
web/
├── index.html                # 入口
├── data/
│   ├── hexagrams.json        # 64 卦（公版原文 + 自撰注解）
│   ├── trigrams.json         # 八卦
│   ├── wings.json            # 十翼
│   ├── theorems.json         # 象数理论
│   ├── almanac-terms.json    # 黄历术语解读
│   └── almanac-yiji.json     # 宜忌映射
├── js/
│   ├── main.js               # 入口：路由、初始化、模式切换
│   ├── data-loader.js        # 加载 JSON + 启动自检
│   ├── hexagram-utils.js     # 位运算：错/综/互/变、爻题、当位
│   ├── svg-painter.js        # SVG 卦象绘制（六爻/八卦）
│   ├── star-map.js           # ★ 力导向星图（Canvas 渲染 + 交互）
│   ├── render.js             # 详情页渲染（长卷阅读式）
```

### 7.3 星图模块（star-map.js）核心职责

- 初始化力导向模拟（d3-force）：节点=64卦，边=错综互变关系
- Canvas 渲染：星点、连线、悬停光晕、状态层叠加
- 交互处理：拖拽旋转、滚轮缩放、悬停预览、点击进详情、搜索定位、连线层切换
- 模式状态层：根据当前模式（复习/测验/占筮/黄历）叠加对应的视觉标记
- 暴露 API：`focusStar(code)`、`highlightRelations(code)`、`setMode(mode)`、`getCenterStar()`

### 7.4 领域内核（沿用且强化）

binaryCode 主键 + 位运算的工程内核完全保留并强化使用：

```javascript
// 错卦（旁通）：每位取反
oppositeCode = code => code.split('').map(b => b==='1'?'0':'1').join('')
// 综卦（反卦）：整体翻转
reversedCode = code => code.split('').reverse().join('')
// 互卦：取 2-3-4 爻为下卦，3-4-5 爻为上卦
interlockingCode = code => code.slice(1,4) + code.slice(2,5)
// 变卦：指定爻位翻转（6 种，每爻各可变）
changingCode = (code, pos) => { /* pos: 1-6 */ }
```

这四个函数驱动星图的全部关系连线、详情页的"它如何变"、测验出题、占筮变卦解读。
