# 易象图谱 UI/UX 设计决策基线

- **设计名称**：天象书院
- **状态**：已确认、持续补充
- **最后更新**：2026-08-15
- **适用范围**：桌面网页与 Windows 本地版

本文件是当前 UI/UX 的单一决策基线。后续讨论形成新结论时，应直接更新本文件并保留变更记录。若旧设计文档与本文件冲突，以本文件为准；算法、内容和数据规则仍以对应 PRD 为准。

## 1. 产品体验目标

项目首先解决“知道《易经》值得学，却不知如何入门、记忆和运用”的问题。体验应依次让用户感到：**愿意进入、看懂关系、知道下一步、通过练习真正掌握**。

整体气质采用“古典知识 × 当代数字产品”，不是仿古网页，也不是游戏大厅。视觉占比约为：60% 可读知识界面、25% 沉浸星图、15% 铜质机械与动效。

## 2. 视觉方向

- 以方案 3 的“天文仪器、星图与铜质机械”为主体。
- 融合方案 2 的暖宣纸、编辑式排版和长文阅读体验。
- 保留方案 1 的全画幅深色星图背景与空间纵深。
- 主色：墨蓝 `#0a0e1a`、铜金 `#c9a96a`、宣纸 `#d8c8a5`、正文墨色 `#2b261d`、朱砂 `#8c4638`。
- 顶部导航约 72px；当前项使用铜金下划线，不使用大面积金色胶囊。
- 使用真实图标，不使用 emoji、乱码字形或字符假图标。

任何装饰背景不得包含生成式文字。AI 或位图只负责无字纹理、星云和仪器材质；所有卦名、经文、方位与刻度文字必须由项目真实数据以 HTML、SVG 或 Canvas 单独绘制。

## 3. 桌面布局状态

当前不开发手机版。桌面端统一使用三种容器状态：

1. **全景探索**：星图占满主视区，用于浏览、搜索、演变和卦序转盘。
2. **专注修习**：学习、复习、测验和修习谱使用约 28% 星图窗口 + 72% 阅读工作台；星图降亮但不消失。
3. **宽幅工作台**：黄历与占筮使用更宽的结构化内容区。

导航顺序固定为：黄历、探索、学习、复习、测验、占筮。卦序不占主导航位置，归入探索模块右上角的探索器。

首次进入提供三条清晰路径：**零基础开始、探索星图、今日一卦**。三者分别进入学程起点、自由星图和当天卦象研读。

## 4. 学习与典籍阅读

学习模块只保留四个一级入口：**今日修习、五阶学程、典籍书库、修习谱**。考评嵌入课程节点，资料与设置不再占用同级标签。

首页优先回答“我在哪里、今天做什么、为什么推荐”。首屏只设置一个主行动“继续研习”，推荐顺序为：继续未完成内容 → 到期复习 → 已检出的薄弱项 → 下一节未学内容 → 复讲或解卦实践。

五阶学程为：蒙学、习经、研传、明辨、通用；全部可浏览，不用锁链阻挡。每阶使用“初识 → 渐悟 → 成章”表达成长状态。

正式课程采用连续纵向阅读，不做翻页拟物。中央暖宣纸正文约 700–740px，右侧深色边注约 250–280px。正文约 17px、行高 1.9，每行约 30–36 个汉字。课程内部统一采用：**引 → 观 → 读 → 解 → 用 → 试**。典籍原文、项目解释、延伸材料和现代类比必须明确标注，不得混写。

## 5. 星图探索与卦象详情

星图是产品的“世界地图”，采用“一图三境”：

### 观天

- 六十四卦为星体，八卦为八个空间锚点。
- 默认仅显示八卦锚点、当前任务和少量关键标签，不常驻展示全部六十四个卦名。
- 标签优先级：当前卦 → 关系卦 → 搜索结果 → 学习任务 → 八卦锚点 → 普通卦象。
- 标签随缩放逐级出现，并进行屏幕空间避让。

### 寻象

第一次点击只聚焦，不立刻打开长内容。镜头平滑靠近，其他节点降至约 20% 亮度，显示包含卦名、序号、上下卦和一句核心含义的微型卡片，并提供“研读此卦”按钮。

综、错、互、变每次只激活一种关系，不能把所有线同时铺满：

- 综卦：金色实线与双向箭头。
- 错卦：朱砂长虚线。
- 互卦：青玉点线。
- 变卦：铜白动态流光。

颜色必须同时配合线型或标记，不能只依赖颜色传达关系。

### 研经

详情默认从底部展开，不回到右侧遮挡星图，采用由浅入深的三个稳定状态：

1. **卦象摘要**：约 96px，只显示卦象图、序号、卦名、上下卦、一句核心处境，以及“展开研读”“回到星图”。
2. **快速研读**：占屏幕高度 42%–48%，至少保留一半星图可见。左侧显示卦象身份，中部显示核心处境、卦辞和简明导读，右侧显示关系入口与学习状态。顶部标签为概览、卦辞、彖象、六爻、关系；笔记和分享保持次级。
3. **深度研经**：进入全屏书院案头。左侧窄栏承载章节目录，中部约 720px 暖宣纸正文，右侧深色边注承载出处、术语、上下卦说明和学习提示；星图只作为外围空间边界。

详情页必须理解用户的来路：由关系线进入时默认打开“关系”，由今日一卦进入时默认打开“概览”，由课程进入时定位到对应经文。关闭详情后恢复原星图焦点和探索路径。

内容顺序固定为：卦象与上下卦 → 一句话处境说明 → 卦辞 → 彖传与象传 → 六爻 → 关系演变 → 笔记与出处。内容类型使用固定标签：`原典`、`项目导读`、`典籍依据`、`现代参照`、`学习提示`。缺少可靠来源时显示“内容待校验”，不得自动补写貌似真实的经文。

#### 六爻阅读

六爻正文按照“初、二、三、四、五、上”的学习顺序向下排列；卦象图仍保持初爻在下、上爻在上的真实空间结构。点击某爻时，只高亮图中对应爻并同步显示爻辞、小象、项目解释和适用边界。存在动爻时播放一次爻线变化，不循环演示、不自动跳到下一爻。

#### 关系对照

关系页采用“本卦 → 变化规则 → 目标卦”的正视对照，不使用旋转卡片。每次只呈现一种关系，中间明确显示哪些爻如何变化，下方同步说明结构变化、含义变化与典籍依据。目标卦提供“在星图定位”和“研读目标卦”两个动作；顶部保留最多五步的探索路径，例如“乾 → 夬 → 大有”，防止用户迷失。

右上角“探索器”整合搜索、演变实验室、卦序转盘与视图设置。搜索支持卦名、序号、六位编码、上下卦和关键词；搜索结果先聚焦星体，不突然打开详情。演变实验室保持探索模块内的独立功能，并可从关系演变区直接进入。

## 6. 修习谱与成就反馈

游戏化比例固定为“雅致书院 70% + 游戏反馈 30%”。学习闭环为：学习 → 小试 → 间隔复习 → 解卦实践 → 反馈 → 成就。

五项能力为：识象、读经、观变、明辨、表达。修习谱包含总览、印谱、能力和观象录。首批十二项成就及达成条件以 [成就学习体系 PRD](achievement-learning-system-prd.md) 为准。

奖励使用铜印、题名、星图表现和可选声景，不使用金币、宝箱、抽卡、体力、强制连续签到或排行榜。成就必须显示达成证据；动画约 1.2 秒，在当前学习结果展示完成后再出现，不遮挡答题或经文。

## 7. 统一修习反馈

测验、复习和解卦共用“修习反馈笺”，每次反馈固定回答：本次表现、判断依据、对学习记录的影响和下一步。反馈以内嵌暖宣纸呈现，不使用遮挡当前结果的庆祝模态框。

统一结构为：

1. **本次结果**：只描述当前表现，不因单次答对宣称“已经掌握”。
2. **依据辨析**：展示正确答案、推导过程、原课或典籍出处。
3. **掌握变化**：说明新增的学习证据、薄弱项和下次复习时间。
4. **下一步**：只保留一个主行动和最多两个次行动。

模块语言映射如下：

- **测验**：使用“本题答对 / 本题未答对”，展示答案、推导和出处；未答对内容进入温故队列。主行动为下一题，次行动可查看原课或演变。
- **复习**：自评改为“暂未想起 / 有些模糊 / 能清楚复述”，并明确标注“基于你的自评”；选择后立即说明下次温故时间和建议重看内容。
- **解卦**：使用初观、得象、有据、明辨、通达，展示定象、取意、援经、成说、知止五维证据；结果分为已做到、尚可补充、推荐修改和典籍参照，不评价现实预测是否应验。

表现稳定使用低饱和青玉，待辨析使用铜金，需要温习使用克制朱砂，未检验使用灰蓝；颜色必须配合文字与真实图标。正确使用轻柔确认声，未答对使用短促低沉的木质触点而非失败蜂鸣；只有完成整组修习时播放一次铜印落定声。反复提交或点击不得重复增加掌握度或成就证据。

## 8. 黄历宽幅工作台

黄历采用“时序仪 + 日课笺”，目标是帮助用户理解一天所处的时间结构，而不是成为简单的吉凶查询器。整体内容比例约为 70% 历法学习、30% 日用速览。

工作台宽度约为 `min(1240px, 100vw - 96px)`，星图背景降至约 15% 亮度。页面分成日期轴、中部时序双区和底部解读三层：

1. **日期轴**：中央显示日期、星期和农历，两侧使用真实箭头图标切换；下方显示连续七天。点击年月打开日期选择器，离开当天后出现“返回今日”。非当天内容统一称“本日解读”。
2. **暖宣纸日课笺**：约占五列，显示公历、农历、年/月/日干支、生肖、纳音、当前节气、进入天数和下一节气。使用“上一节气—当前—下一节气”的真实计算进度，不绘制虚构刻度。
3. **深色择日资料**：约占七列，依次展示建除与值宿、宜忌、彭祖百忌。宜忌使用两列清单而不是密集胶囊，青玉和朱砂必须同时配合文字或符号。
4. **本日解读**：默认展开“时序是什么、民俗怎样理解、今天可以学什么”三段，并分别标记 `历法计算`、`民俗资料`、`项目导读`。

点击术语时更新工作台内的“术语笺注”，不使用打断阅读的模态框。黄历右下方可显示明确标为“项目今日一卦”的入口，点击后关闭工作台并在星图中聚焦对应卦；不得将其伪装成传统黄历固定组成。

日期切换只让数字与时间轴按方向移动，其余内容交叉淡入。使用轻微 `uisfx` Zen 步进声；只有用户主动跨越节气日期时可增加一次短促古典音色。术语、宜忌点击保持安静。分享功能生成“今日历笺”图片，只包含公开日期资料、简要解读与文化学习边界。

## 9. 占筮后的学习挑战

起卦后提供：引导解卦、自主解卦、直接研读。解卦练习依次完成：**定象 → 取意 → 援经 → 成说 → 知止**。

评价维度为定象、取意、援经、成说、知止，各 20 分；称号为初观、得象、有据、明辨、通达。本地端只校验结构化、可验证内容，不假装完全理解自由文本，也不按现实事件是否发生评价“占得准不准”。用户问题和私人笔记默认不保存；进入观象录必须主动确认。

## 10. 星图、铜器与宣纸材质

每个页面只能有一种主材质，三者不得以同等强度竞争。场景占比约束如下：星图探索为星图 70% / 铜器 20% / 宣纸 10%；学习研经为宣纸 65% / 星图 25% / 铜器 10%；黄历为宣纸 45% / 星图 35% / 铜器 20%；转盘与成就为星图 45% / 铜器 45% / 宣纸 10%。

### 星图

星图由墨蓝纯色底、极弱无字星云纹理、Canvas 真实星体与关系线、局部天文仪器边缘组成。普通星、关系星和当前星使用三级亮度，当前星只能有一圈主光；背景颗粒约 2% 且保持静态。

`web/assets/academy-astrolabe-bg.webp` 仅用于开场和少数探索场景，需降低铜环亮度并控制仪器占画面不超过约 20%，不得代替真实关系星图，也不得反复出现在学习、复习和测验中。

### 铜器

铜器采用哑光、有重量的统一色阶：深铜阴影 `#3b2615`、基础铜色 `#8a6030`、柔和高光 `#c9a96a`、少量边缘亮光 `#e4cb8b`。铜质纹理只用于转盘、机械锁定、成就印章和主操作边缘，普通按钮、标签与卡片不做金属化。

机械动作必须符合质量感：转盘加速后衰减并以棘轮锁定；印章垂直落下、不旋转飞入；爻线像机构咬合；普通按钮只做约 1px 压下反馈。`web/assets/taiji-mechanism.webp` 的细环存在类似伪文字的刻痕风险，发布前必须替换为无文字版本，或完全遮蔽刻度并以真实数据层重绘。印章名称始终使用实时文字，不写入生成图片。

### 宣纸

宣纸表现保存良好的书院用纸，不使用烧焦边缘、茶渍、撕裂、木轴或夸张折痕。基底为 `#d8c8a5`、正文 `#2b261d`、次级文字 `#625746`、朱砂批注 `#8c4638`，纤维纹理透明度控制在 4%–6%。纸张圆角为 6–8px、阴影轻微，正文不得使用金色小字。

宣纸只用于课程正文、卦象深度研读、日课笺与修习反馈；导航、工具栏和外部容器保持墨蓝。全项目光源统一来自左上方，铜器高光、纸张阴影和按钮压下方向必须一致。所有图片只提供无字材质，信息来自真实 HTML、SVG、Canvas 和项目数据；灰度、125% 与 150% 系统缩放下仍须保持层级与文字清晰。

## 11. 声音与动效

`uisfx@0.4.0` 只作为少量常规界面声音的候选素材源，不作为全局声音系统。铜钱、棘轮、转盘停靠、纸张、毛笔、印章与传统乐器继续使用独立真实拟音，不以基础 UI 声替代。

第一轮评审已在 [界面音色试音室](auditions/uisfx-2026-08-15/index.html) 完成：保留 `volume-change`、`open`、`close`、`expand`、`collapse`；待定 `select`、`toggle-on`、`toggle-off`、`mechanical/snap`；弃用全部九项 Zen 学习反馈声音，以及 `mechanical/lock`、`mechanical/unlock`。`uisfx` 不再承担学习奖励、纠错、课程完成、成就或核心机械锁定声标。

试听采用 A/B 两版：A 保留素材原声；B 在大致响度匹配的前提下补入主体、触点和克制短尾韵。Zen 的增强方向是温润木质与轻空间感，Mechanical 的增强方向是更低的铜质重心、明确金属接触和短促腔体回响。B 版只是音色方向验证，不能替代铜钱、纸张、毛笔、印章和转盘棘轮的真实拟音。

**最终版本方向选择 B 质感增强。** A 原声只保留为评审对照；第一轮保留的五项声音，以及后续通过评审的四项待定声音，均以 B 版处理参数作为正式接入基准。已经弃用的学习反馈与机械锁定、释放声音不得因选择 B 而重新启用。

正式声音必须由业务状态成功改变后显式触发，不能只根据按钮类名或 document 级事件冒泡猜测语义。复习的“忘了 / 模糊 / 记得”属于自我报告；在第二轮学习声景通过试听前，选择和保存动作保持安静。占筮的完成声必须在结果生成并落定后播放，而不是在点击起卦按钮时提前播放。

不播放悬停音、打字音或持续缩放音。第一次用户交互后再加载音频，提供总静音和音量控制，并设置并发与冷却。保持静态站点架构：开发阶段可通过 npm 选音，发布时只随项目分发经确认的少量资源及许可说明，不提交完整依赖目录。

## 12. 可用性与性能底线

- 1280×720 和 1440×1024 是主要验收视口。
- 键盘支持搜索、关系节点切换、Enter 聚焦或研读、Escape 返回或关闭。
- Canvas 提供等价的 DOM 焦点列表与必要的读屏信息。
- 动效支持 `prefers-reduced-motion`，批量动画结束后保留稳定阅读时间。
- 设备像素比建议上限为 2；页面隐藏或进入专注工作台时暂停不必要的星图动画。
- 标签碰撞和关系计算不得在每个绘制帧完整重算。
- 分享内容不得包含私人占筮问题、自由笔记或内部配置。
