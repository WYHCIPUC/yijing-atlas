| 轴 | 说明 |

| 实现 | 起卦、取辞、解释、历史与成就引擎已有；五步挑战、观象录和若干成就达成路径尚未完整实现。 |

“当前事实”是代码行为；“目标规格”是应建设结果；“执行默认”是本总册为后续AI锁定的实现口径。
存在某个成就名称或引擎函数，不等于用户可从界面达成；存在五个自评框，不等于已实现五维客观评阅。

### 1.1 术语

| 名称 | 定义 |
| --- | --- |
| 本卦 | 本次起卦得到的六位阴阳码，自初爻到上爻。 |
| 之卦/变卦 | 指定动爻翻转后的卦；没有动爻不伪造不同结果卦。 |
| 动爻 | 金钱法老阴/老阳对应的位置；梅花法明确的一条变化位置。 |
| 取辞政策 | 解释本次为何选择某条卦辞/爻辞的流派规则，必须有版本与边界。 |
| 起卦历史 | 默认保存的技术复现记录，不含私人问题和自由笔记。 |
| 观象录 | 用户主动确认保存的学习分析记录；与自动历史不同。 |
| 结构检查 | 只核对编码、爻位、规则、引用定位与选项等可验证内容，不声称理解自由文本。 |
| 成就事件 | 带稳定subjectId、idempotencyKey和受限metadata的学习证据。 |
| 修习谱 | 面向用户查看证据、能力、印谱和观象录的学习页面。 |

### 1.2 不变量

- 起卦只用于文化学习与反思，不按现实事件是否应验判分，不给现实决策确定结论。
- 不改六位码底到顶约定；卦图初爻在下，正文/步骤位置需明确。
- 不改变现有取辞政策或梅花算法来迎合界面；算法变更必须有专项依据和回归。
- 原典、经传、象数传统、术数方法、项目类比须分层，不把项目解读冒充古籍原文。
- 私人问题和自由笔记默认不保存、不导出、不分享；主动保存时明确范围并允许删除。
- 不因起卦或随机抽取就增加正式深读、复习卡或“分析正确”的成就。
- 不用金币、抽卡、强制签到、体力和排行榜推动学习；修习谱比较的是个人证据。
- 对重复点击、重放和保存重试使用稳定幂等，不能用新时间戳绕过去重。

## 3. 主入口、页签与当前步骤

### 3.1 当前事实

占筮是六主导航之一；工作台含金钱卦和梅花页签，支持鼠标和左右/Home/End键。
金钱页面展示净心、定问、六掷、读经说明；实际一次点击立即生成六次完整随机结果。
当前没有真实“逐次投掷六次”的状态机，文案中的六掷不能被交接文档当成已实现动画过程。
没有私人问题输入框；用户心中定问，不代表系统保存了问题。

### 3.2 目标规格

- 顶部明确方法、当前步骤、文化学习边界、历史入口和返回方式。
- 方法切换不自动起卦；未确认的新输入留在当前方法内，不将随机结果写成用户输入。
- 本轮执行默认保留“一次生成完整金钱卦”的算法调用，不把逐次掷币动画作为隐含新增范围。
- 若后续建设逐次掷币，必须另设六次完整会话和取消规则，不能只把同一结果切六段当六次真实采样。
- 按钮在结果生成期间防重复；用户明确“再起一卦”才创建新cast。
- 关闭工作台回探索，不自动创建额外历史、卡片、成绩或成就。
- 页签和关闭使用原生按钮语义，选中页签aria-selected、tabpanel关系同步。
- 空态解释操作前置；局部错误保留输入并给重试，不回全站欢迎页。

### 3.3 验收

- Given 首次进入占筮，When 没按起卦，Then 无自动历史新增。
- Given 使用键盘切梅花，When 输入数字，Then 不被页签异步焦点拉回标题。
- Given 点再起一卦，When 新结果生成，Then 有新cast标识而非复用旧分析会话。
- Given 关闭工作台，When 回探索，Then 不把关闭视为完成一次分析。

## 4. 金钱卦、动爻和取辞

### 4.1 当前事实

每枚硬币取2或3，三枚之和6/7/8/9分别得到老阴/少阳/少阴/老阳；6与9变化。
castHexagram按初至上生成yaos，本卦按value拼码，之卦翻转所有changing位置。
结果图象展示顺序为上爻到初爻，并明确标注；不能反转底层yaos数组来满足展示。
取辞政策标识zhu-xi-qimeng-v1，界面应说明“后世常见取法之一”，不是本经唯一占法。

| 动爻数 | 当前规则，必须保持并可复现 |
| --- | --- |
| 0 | 本卦卦辞。 |
| 1 | 本卦动爻爻辞。 |
| 2 | 本卦两动爻，较上者主、较下者参。 |
| 3 | 本卦卦辞主、之卦卦辞参。 |
| 4 | 之卦两不变爻，较下者主、较上者参。 |
| 5 | 之卦唯一不变爻爻辞。 |
| 6 | 本卦乾取用九，坤取用六；其余取之卦卦辞。 |

### 4.2 字段、状态和输入

- 完整cast需六条yao、每条三枚硬币、isYang、changing、本卦码、之卦码和变化位置。
- UI验证六位码、位置1—6、布尔值与硬币结果一致；不接受只有卦名没有结构的“完整结果”。
- 没动爻时显示“六爻皆静”，不强制绘制不同之卦；研读入口可只显示本卦。
- 正常结果包含本卦、之卦、全部动爻、取辞来源、主参、方法边界及下一步。
- 字段缺失时显示本次结果不完整，不套用其他卦解释；来源缺失标待校验。
- 结果生成失败保留方法页面和重试按钮；保存失败不否定已生成结果，但不能显示已入历史。
- 鼠标触控一按生成，键盘Enter/Space同等；动画不是取得结果的前置条件。
- 减少动态效果直接落定；完成声音应在结果真实生成并落定后显式触发，不能以点击类名猜测成功。
- 新cast入自动技术历史并记录活动；打开历史重放不新增cast和活动完成证据。

### 4.3 验收

- Given 固定六次硬币结果，When 起卦，Then 本卦、全部动爻和之卦与纯逻辑完全一致。
- Given 2/4动爻，When 查看主参，Then 主爻分别按上/下规则，不因DOM逆序而交换。
- Given 乾六爻全变，When 取辞，Then 用九；坤同理用六；其他全变取之卦卦辞。
- Given 写入存储失败，When 看结果，Then 可继续读经并清楚标未保存历史。

## 5. 梅花数字法与时间简化法

### 5.1 当前事实

上数、下数默认随机1—99；输入必须为1以上安全整数，且和也是安全整数。
上数除8定上卦，下数除8定下卦，总和除6定动爻；整除取8或6，不取0。
本卦拼接下卦码+上卦码；动爻1—6翻转一位形成之卦。
时间法用设备本地公历年月日时简化换算；它不是严格农历或北京时间历法推演。
当前已经标“公历简化”；不能在界面升级中删掉这一方法边界。

### 5.2 目标规格

- 数字字段有上数/下数明确label、min=1、step=1、numeric输入提示，不能仅靠placeholder。
- 空、0、负数、小数、NaN、Infinity、不安全整数或和溢出均不得起卦。
- 错误就地提示，aria-invalid与描述关联，聚焦首个错误字段；修改输入后清旧错误。
- 时间法明确展示当次取时的时区/时间来源；执行默认保留现有本地时间算法，不借UI任务改为农历算法。
- 结果包含本卦、之卦、唯一动爻、体用五行关系、原文证据、项目解释与方法局限。
- “吉凶”类传统术语必须放在流派语境中，不输出对具体医疗、法律、财务等现实结果的保证。
- 数字法和时间法结果保存各自method与source，重放不重新取当前时间。
- 输入与结果进入快深读时通过来路上下文保存，不因返回重新随机默认数字。

### 5.3 验收

- Given 上下数都8，When 起卦，Then 上下卦按余0取8、动爻按总和余6计算，不产生第0爻。
- Given 两个各自安全但和溢出的整数，When 起卦，Then 明确拒绝，不执行精度损失计算。
- Given 时间法旧记录，When 次日重放，Then 原卦与取时source不改变。
- Given 无效数字，When 提交，Then 不写历史、不发完成音、不增加成就。

## 6. 结果解读、来源和边界

当前解释区包含当前处境、关键提醒、变化方向、取辞方法、术语、经文证据、现实类比和反思三问。
这些是由本地资料和项目模板生成的学习说明，不是联网AI洞察或对私人问题的理解。

- 每条证据能标明对应卦、爻、主参和来源层；引文与项目白话分开显示。
- 解释来源使用保存时版本；旧记录缺解释可说明缺失，不假装保存时已有最新解释。
- 私人问题没有提交给系统时，不写“已理解你的问题”或定制结论。
- 正常结果先给可核对结构，再给类比；类比明确不是预测。
- 无项目解释时允许只读经文和规则；不能用生成文本填充貌似完整的古籍注解。
- 每次只保留一个主行动进入学习挑战，次行动进入本卦/之卦研读；避免结果页堆满同权按钮。
- 长解释可折叠，但本卦/动爻/取辞政策和边界不可全部藏到深层。
- Given 缺某条项目说明，When 打开结果，Then 仍展示真实结构和原文，明确待补内容。
- Given 从历史进入，When 查看来源版本，Then 与保存快照一致，不悄悄改写当时理由。

## 7. 自动历史与稳定分析ID：T-DIV-01

### 7.1 当前事实

自动历史使用yijing-divination-history-v2，最多50条；合并v1旧摘要并按时间倒序。
v2保存六爻、全部动爻、梅花cast、取辞政策、解释及解释版本；不保存私人问题和自由笔记。
旧摘要显示“不可复现原推理”，仅可研读本卦，不伪造老少爻、完整动爻或解释。
新分析的analysisId当前含Date.now；梅花历史重放传history:id，金钱历史重放未统一传入稳定ID。
因此同一金钱历史反复重放并提交自评，可能被记成多个独立分析。

### 7.2 目标与执行默认

- 每次用户明确新起卦生成稳定castId；该cast的历史、分析和阅读来路共用标识。
- 自动历史item.id作为重放标识，不以重放时间创建新castId。
- 执行默认分析subjectId为castId派生的稳定值，首次提交和修改区分事件类型，不换subjectId。
- 保存新cast后使用实际返回的item.id；保存失败则保留本次运行内稳定ID，直到明确重起一卦。
- 历史重放不调用随机引擎，不追加历史，不重复记录“新起卦完成”。
- “清空起卦历史”只清技术历史；相关已获得成就不默默回滚，观象录删除范围另行说明。
- 清空失败保持原列表并提示；空历史给方法入口；损坏记录跳过或显式不可用，不导致整页崩溃。
- 同一记录无论金钱/梅花重放，分析结果均归同一subject；新cast即使六位码相同仍可有新subject。
- 数据迁移不可用新时间伪造旧记录创建时间；旧摘要只保持摘要身份。

### 7.3 验收

- Given 一条金钱v2记录，When 重放三次并重复提交，Then 历史数不变、分析subjectId不变、成就不重复增加。
- Given 同一卦再次主动起卦，When 提交新分析，Then 是新castId，不被当成旧记录重复提交。
- Given v1只有本卦/之卦摘要，When 重放，Then 明确缺失信息，不展示伪造取辞与爻老少。
- Given 清空写失败，When 查看列表，Then 不显示已清空；重试不会触发新起卦。

## 8. 五步解卦学习挑战：T-DIV-02

### 8.1 当前差距

现有“完成一次研读”只是五个checkbox，各勾选20分，提交后写成就并禁用按钮。
它是主观自报，不验证本卦、动爻、引用或推理；不等于定象→取意→援经→成说→知止五步挑战。
后续必须保留旧自评记录的真实性身份，不能迁移为客观核验过的证据。

### 8.2 入口和会话

- 结果后提供引导解卦、自主解卦、直接研读三个入口；只有前两项创建挑战会话。
- 引导和自主使用同一cast与校验规则；引导逐步提示，自主可先填后统一核对。
- 直接研读不生成分析分数或“分析完成”事件，只按正式阅读规则记录。
- 会话保存castId、方法、规则版本、当前步骤、结构化回答和提交状态；自由正文默认仅内存。
- 每一步可返回修改；最终提交前不写正式分析成就；暂存不得偷偷保存私人文本。
- 刷新无主动保存的分析草稿即失去；页面提示清楚，不默认声称已备份。

### 8.3 各步骤字段和本地核对

| 步骤 | 必填内容 | 可核对与不能声称的部分 |
| --- | --- | --- |
| 定象 identification | 本卦、之卦、上下卦、全部动爻 | 与cast纯函数核对；无动爻应明确六爻皆静。 |
| 取意 imagery | 选择本次重点位置、取辞政策、主参对象，写项目处境理解 | 位置/规则/主参可核对；自由处境解释不当作机器已理解。 |
| 援经 citation | 从可用证据中选择卦辞/爻辞/传文，保留来源定位 | 定位、引用存在性和主证一致性可核对；不给未校原典“已审定”标签。 |
| 成说 reasoning | 选择变化规则与事实/类比/推断类别，写自己的说明 | 规则和分类题可核对；连贯性与现实推论需人工或自评补充。 |
| 知止 boundary | 选择证据不足项、现实事实待核对项、适用边界判断 | 结构化边界题可核对；不能仅勾“我已知止”就取得客观满分。 |

- 自由说明执行默认20—1000字；长度只验证可提交格式，不作为理解正确的证据。
- 定象枚举来自当前真实卦象数据，动爻为1—6的无重复集合；不能靠文本相似匹配位置。
- 援经仅可选当前可引用材料；引用须有hexCode、kind、position可选、source层和实际文本。
- 用户自行粘贴引文可作为未核验补充，不能冒充系统已定位来源或自动提升“引经有据”成就。
- 取意、成说、知止的客观检查题使用有明确正确条件的本地题库；题库缺失时标未检验，而非随意判对。
- 任何题库答案都必须能回到规则或资料依据；不得将“与项目解释措辞相同”作为唯一正确答案。

本轮结构检查点按下表固定。每格是可单独复现的布尔检查，正确得5分，错误得0分；缺少所需资料时标未检验。

| 维度 | 四个检查点，按顺序固定 |
| --- | --- |
| 定象 | 本卦码正确；之卦码正确（无变明确同卦）；全部动爻集合完全一致；上下卦码均正确。 |
| 取意 | 主证kind正确；主证所属卦码正确；主证爻位正确（非爻辞应为无爻位）；主证内容层正确。 |
| 援经 | 选中主证定位与getReading结果一致；引文与该字段一致；主参证据集合完整；主参优先级标记正确。 |
| 成说 | 取辞政策标识正确；指出翻转位置恰为本次动爻；能把给定原文/项目白话例句分到正确层；把结构→取辞→类比→现实事实核对排成正确顺序。 |
| 知止 | 对“卦象足以确定现实结果”选否；对“此取辞法是本经唯一方法”选否；对“现实判断还需核对事实”选是；对“无法证明私人情境相符时应保留判断”选是。 |

- 引导模式可提前展示规则，但正式检查必须由用户明确选择，不能用预填答案自动计分。
- 对梅花，主证与规则根据buildMeihuaInterpretation实际证据生成；不得强套金钱法getReading的多动爻政策。
- 引文一致性只做换行统一与首尾trim，不做语义近似；选择定位后自动显示引文，核对的是选中正确来源，不冒称用户背诵正确。
- 没有参证时，“主参集合完整”要求用户明确本次无参证，不能以空字段悄悄得分。
- 用九/用六的position为空且kind保持useNine/useSix；不能伪装成第七爻。
- 成说和知止的分类/排序/是非题采用固定可访问选项；自由文本单独保留，不参与这20个布尔检查。
- 这套检查验证结构与方法知识，不验证私人叙事真实性、自由说明质量或现实判断效果；反馈中必须重复这一边界。

### 8.4 分数、称号与诚实反馈

五维各20分。执行默认每维四个有规则依据的结构检查点、每点5分；具体题目和正确条件随规则版本固定。
同一维缺少有效检查点时，该维标“未检验”，不能用checkbox或文本长度补足到20。
自由文本仍展示给用户自查，结果明确“本地结构检查分”，不称客观理解分或现实预测能力。
不足完整五维时显示已检验分与未检验项，不给完整总分称号；未检验不等于用户答错。
完整检查后称号执行默认如下，若上位PRD另有阈值，以更新后的统一规则为准，不同时维护两套阈值。

| 结构检查总分 | 称号 | 表达边界 |
| --- | --- | --- |
| 0—39 | 初观 | 初步识别；建议回看结构。 |
| 40—59 | 得象 | 有部分结构依据。 |
| 60—74 | 有据 | 主要证据已形成，仍需辨析。 |
| 75—89 | 明辨 | 本轮结构检查较完整，不能等同现实判断正确。 |
| 90—100 | 通达 | 本轮检查完整，仍保留流派、原文和现实边界。 |

称号明辨从75开始与当前成就引擎reasoned-reading阈值一致；不能在界面改80而引擎仍75。
五维结果固定展示已做到、尚可补充、推荐修改、典籍参照；无可核对内容就明确说明缺失。

### 8.5 幂等、修改与失败

- 首次完整提交用divination.analysis.submitted，修改用divination.analysis.revised；subjectId固定为同一cast分析。
- 同一版本重复提交复用幂等键；有效修改才产生新revision，不用Date.now强制绕过去重。
- 新版证据采用metadata.learningPath=guided|independent，metadata.assessmentVersion=structure-v1；direct只阅读，不发挑战分。这是待实现契约，当前事件白名单/聚合尚未接通，T-DIV-02同步更新。
- “言之成理”仅计independent、完整新版结构检查至少75分的不同案例；guided即使满分也不计该项。其他成就按各自条件检查。
- 一旦本案例挑战展示了引导答案/步骤提示，证据路径固定guided；之后切自主视图不把同案例重标independent。新案例可重新选择，自主内容仍可自由阅读原典，不做侵入式反作弊。
- 一个subject在成长汇总中只算一次分析；新版可提高同一subject的最佳证据，但不重复增加“次数”。
- 保存失败时保留结果和回答，显示哪些未保存并可重试；不重掷、不丢自由正文。
- 无法核验的自评部分独立标记，不设置cited/changingLinesCorrect等客观标志。
- 已存在旧checkbox分析在证据UI标“历史自评”；执行默认不撤销已获印章，但新进阶事件必须按新检查规则生成。

## 10. 观象录与主动保存：T-PRIV-01

### 10.1 当前事实与边界

当前只有自动技术历史，没有符合基线的观象录页面与主动保存完整学习分析流程。
自动历史不保存私人问题/自由笔记；这项保护必须保留，不能因新增观象录而全部自动保存。

### 10.2 执行默认规格

- 挑战完成后提供次行动“保存到观象录”；默认不勾选保存，不因完成挑战自动加入。
- 保存前展示内容清单：公开卦象结构、取辞政策、结构化回答、评分证据；私人问题和自由说明分别独立确认。
- 默认仅保存公开结构与结构化学习证据；私人问题/自由说明即使已经输入，也保持未选中。
- 本轮存储仅当前浏览器，列表、详情、删除、导出范围在数据专题统一；不做云上传。
- 每条记录有稳定id、castId/analysisSubjectId、创建时间、规则版本、证据来源和私密字段存在标志。
- 观象录与自动历史互相引用；删除技术历史不自动删除独立主动保存记录，必须明确说明。
- 删除观象录不默默回滚已得成就。当前没有全站“清除全部学习数据”入口；未来若另建，必须先明确定义清除范围与备份恢复，不在本任务中暗加清除动作。
- 公开分享只从公开模型生成，不把观象录的私人字段加入图片、URL、系统share text或诊断日志。
- 导出私人备份前说明可能包含主动保存的私密内容；公开验收包不附真实用户备份。
- 存储拒绝/配额失败显示保存未成功，保留本次内存内容可另行处理；不暗中发送到外部地址。

### 10.3 验收

- Given 输入了私人问题但未确认保存，When 结束挑战并刷新，Then localStorage与备份中均无该问题。
- Given 只保存公开结构，When 看观象录和导出，Then 无自由问题/说明文本。
- Given 明确勾选保存某段私人说明，When 再次查看，Then 能看到私密标志并可单独删除该记录。
- Given 有私人观象录，When 生成公开分享，Then 图片、链接和text不含私密字段。
- Given 保存失败，When 返回结果，Then 明确未保存且未创建空壳记录。

### 12.4 状态、输入与验收

- 空：零印章也展示路径和真实未完成条件，不制造“今日获得”占位奖励。
- 加载：本地数据读取期间有稳定框架，不先显示0后闪成满级；坏数据按存储恢复规则处理。
- 错误/保存失败：成绩可读，回补未保存局部提示；不通过覆盖空对象“修好”私人记录。
- 鼠标/触控点击印章打开证据；键盘可达全部印章，焦点返回原项；能力条有文字数值说明。
- 手机单列，长条件换行，证据时间和来源不被省略到无法辨别；200%实际缩放需独立验证。
- Given 已解锁印章，When 打开详情，Then 看到真实时间、current/target与可定位来源，而不只有条件文案。
- Given 没有观象录，When 进入分区，Then 说明需主动保存且不自动搬入所有技术历史。
- Given 连续进入修习谱，When 检查课程回补事件，Then 幂等稳定，不重复增加进度。
- Given 学程L4但修习学阶仍蒙学，When 看页面，Then 两种字段有清楚名称，不解释为数据冲突。

## 13. 数据、声音、模态与适配的共同要求

- 技术历史、主动观象录、成绩、成就与呈现草稿分层存储；统一备份与迁移以数据专题为准。
- 本轮不增加私密数据外发；AI评阅协议仅属于学习复讲，不能自动套用到占筮私人问题。
- 起卦完成声音、保存成功声音和解锁落印只能由实际业务结果显式触发，不由document冒泡按class推断。
- 自评和失败保存保持诚实反馈；不能播放使人误认已达成的音效。
- 主工作台、历史、证据详情与阅读抽屉遵循统一模态栈；顶层Escape只关闭顶层。
- 页面隐藏、遮罩、深读和模式切换的暂停原因独立；关一层不启动仍被另一层暂停的动画。
- 减少动态效果直接展示稳定结构，不删掉本卦/之卦、取辞或关闭能力。
- WebGL失败保留Canvas与全部起卦、解释、挑战、记录、阅读；这些功能不依赖3D成功。
- 不把视口截图等同真实手机；触控、键盘、200%真实缩放和读屏各自留证。
