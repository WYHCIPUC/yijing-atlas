## 1. 任务选择和状态规则

- 需求：已确认 / 建议改进 / 未来独立方案。
- 实现：已实现 / 部分实现 / 未实现 / 受门禁阻塞；卡中另列当前验证边界。
- 依据：代码已确认 / 行为已复现 / 待验证假设。推断风险不能直接当已复现故障。
- 执行：待执行 → 复现/规格核对 → 实现中 → 验证中 → 完成；外部阻塞另记，不删除已做部分。
- 首个推荐动作是 T-QA-01；其他任务按各自原卡前置判断，可独立实施并取得专项证据。没有T-QA-01前置的卡不新增这项阻塞；专项通过也不替代T-QA-01自身尚缺的证据。
- 表格排列不替代依赖；选择依赖已满足的任务。外部验收和未来发布不能因其他任务完成而自动通过。
- 依赖满足表示完成条件确实满足，不是只标了一个勾。完成任务必须附源码身份、实际验证和未验证项。
- 每个功能改动只做该卡目标；算法/六位码/隐私/内容门禁遵从总册，不能顺手重写。
- 需要引入新持久字段时，将schema、validator、迁移、导入导出与对应08专题同任务更新；不把未来字段写成现状。
- 并行代理必须声明文件所有权；main.js、render.js、共享CSS、package.json和SW由单一集成者串行合并。
- 低风险可逆实现按已确认规格自主执行；缺外部校对、素材许可、设备时明确记录所需输入，不伪造。
- 远程发布仅T-RELEASE-01且须用户另行提出。本文档任务本身不授权发布。

## 4. 所有执行卡共用的工作协议

1. **核对**：记录分支、HEAD、已有diff、任务现状和需求版本；检查前置任务是否真的完成。
2. **复现**：先执行卡中边界/失败场景，建立能失败的最小回归；纯规格补全可先写关键新行为测试。
3. **实现**：只改允许文件范围，保留原生架构和现有模块；若根因不在计划文件内，记录证据并由集成者调整所有权。
4. **验证**：跑卡中相关测试，再按影响跑validate/E2E；有界面行为必须真实输入，不只脚本click。
5. **审阅**：检查数据/接口兼容、隐私、加载失败、旧数据、键盘、触控、减少动态、离线与保存失败；检查diff。
6. **证据**：在新run目录保存脱敏摘要、必要截图和测试输出，包含版本、环境、命令、退出码及限制。
7. **收尾**：更新本卡执行状态、相关专题和交接；未验证/失败保留，不能仅因代码写完就标完成。

**每张卡共用非目标**：不改变历法/关系/占法口径，不新增账号/云同步/管理后台，不清空用户数据，不绕过内容门禁，不执行远程发布。

**证据路径约定**：docs/qa/<执行日期>/<任务ID>/<run-id>/；不要覆盖历史或提交私人备份。参数化截图尚未实现前先处理T-QA-03或明确保存位置，默认测试不设置截图开关。

**共用回滚**：先留当前任务改动清单和数据备份方案，仅回退本卡自己产生的代码/文档与可逆迁移；禁止git reset --hard或整文件覆盖他人修改。已经发布的新数据格式不能简单删除字段，需要向后兼容读取与明确恢复步骤。

- **命令 / 断言**：隔离有Git/无Git质量runner测试；npm run check；复制文档核对。命令在仓库根目录；历法通过统一runner，参数与实际退出码写证据。
- **完成条件**：两种环境命令、范围、失败和证据明确。
- **外部输入 / 未验证**：尚未实施本卡；先复现现状，不能沿用引擎夹具或旧截图宣称新路径通过。
- **回滚 / 交接**：采用第4节的只回退本卡改动协议；新存储保留兼容读取，不删除真实数据；附已改文件、结果和下一动作。
- **执行记录**：待执行。实施AI在此追加日期、源码、步骤、实际检查、证据路径、剩余项，不覆盖当前事实快照。
