## 2. 本轮确认的三个产品问题

### 2.1 阅读章节边界：T-QA-01

入口为星图聚焦后进入快读，使用真实鼠标切换“六爻”“彖象”等章节。此前默认 E2E 出现“快读六爻章节未响应真实鼠标”。

`web/js/main.js` 的章节滚动监听此前使用“阅读面板顶部 + 工具栏高度 + 32”作为观察线，与章节 `scrollIntoView` 实际采用的 `scroll-margin-top` 不一致，且没有完整考虑边框和工具栏当前位置。章节边界落在取整附近时，滚动监听可能将当前项退回上一节。

本轮修改：

- 以面板内容边缘、工具栏实际底部和章节计算样式中的 `scroll-margin-top` 共同确定观察线。
- 对浏览器像素取整增加 2px 容差，防止上一节抢回已定位章节。
- 没有删除章节检查，没有将 `aria-current` 的唯一性要求放宽，也没有用任意增长的超时替代修复。
- `web/test/main-stage-lifecycle.test.mjs` 增加边界回归，覆盖该滚动监听的状态更新。

此修复处理已确认的章节状态问题；不能据此认定所有旧“六爻未响应”输出只有这一个原因，后续还发现输入坐标处于过渡中的独立问题。

### 2.2 星图命中与画面不一致：T-QA-01

`web/js/star-map.js` 之前在命中测试及 DOM 标签坐标计算时重新将世界坐标投影到屏幕，而浏览器上仍可见的画面来自最近一次完成绘制的帧。镜头、节点或尺寸发生变化时，两者可能不同步。

本轮修改：

- `_nodeAt` 使用节点最近绘制的 `_screen`，与用户看见的星点一致。
- `_nodeViewportPoint` 同样使用最近绘制的屏幕位置，避免控件与画面使用不同参照。
- `resize` 清空旧 `_screen`；没有新绘制位置时不使用旧尺寸坐标命中。
- `web/test/star-map-performance.test.mjs` 增加回归，覆盖绘制位置命中及尺寸变化后的缓存失效。

这是一项有代码和回归支持的命中一致性修复。旧记录 B-01 的画布鼠标选星失败发生时没有足够诊断信息，**不能回溯断言 B-01 唯一由此问题造成**。

### 2.3 新结果和历史回看重复计作不同案例：T-DIV-01

修改 `web/js/modes/divination-mode.js` 的身份传递与结果提交绑定，以及 `web/js/divination-history.js` 的新 ID 生成；不改变随机起卦、六位编码、取辞、原解释、历史数据格式和私人文本规则。

第一轮失败测试实际渲染占筮界面，触发历史按钮和分析提交事件。同一金钱 V2 历史两次重放分别生成 `coin:111111:111111::1001`、`coin:111111:111111::1002`，`metrics.analyses` 从一个案例变成两个。补传 `history:${item.id}` 后，该重放重复计数消失。

继续检查首次结果与首次回看，发现：

- 金钱、梅花首次结果使用时间派生 ID，保存历史后回看使用 `history:id`，仍会形成两个分析 subject。
- 历史保存失败时，固定在同一毫秒的两次相同起卦可能碰撞临时分析 ID。

第二轮先补 4 条失败测试，再做最小修改：

1. `recordCast` 在成功保存时返回历史存储实际生成的 `item.id`。
2. 金钱、梅花首次结果在绑定分析提交前均采用 `history:${item.id}`，与回看一致。
3. 历史保存失败则保留当前结果的时间加运行内序号 ID；绑定闭包重试沿用该 ID，下一次明确新起卦产生独立 ID。
4. 历史回看维持 `record:false`，不再起卦、不增加历史；旧摘要只提供研读入口，不伪造六爻或分析。

新建 `web/test/divination-replay.test.mjs` 的 8 项集成回归覆盖：

- 金钱 V2 重复重放、低分再次提交、导出导入后的再次重放。
- 梅花完整历史重放。
- 旧摘要不生成分析或补造六爻。
- 主动新掷相同卦码仍是两个案例。
- 金钱、梅花首次结果与首次回看沿用一个 subject。
- 两种方法历史保存失败后的重试稳定，以及同毫秒新起卦独立。

测试使用保留真实控件监听器的轻量 DOM 夹具并调用实际渲染、存储和成就模块；不是源码字符串断言，但也不能替代浏览器布局、焦点或设备输入验收。

独立审查进一步复现：历史满 50 条，同一 ISO 毫秒内连续新增会令原 `${createdAt}-${existing.length}` 产生相同 ID。新增回归先出现 `51 !== 52`，随后改为创建时间加 128 bit 随机十六进制后缀，52 次同毫秒新增全部独立；存量 ID 不迁移，重新加载保持 ID。另测随机源抛错，旧历史不变且返回保存失败，结果页保留临时分析身份。两项历史边界回归均通过。

本卡的案例身份与重放幂等目标已完成。首次提交与修改提交分别使用 `submitted/revised` 的语义调整留给 T-DIV-02，本轮没有宣称完成该挑战重构。

## 3. E2E 的第二层输入问题与修正

上述产品修复后，本轮早期两次默认 E2E 仍停在快读六爻检查，因此没有立即把任务标为浏览器通过。

集成者进一步采集到面板横向过渡过程：`left` 从约 `-788.477` 变化到 `-373.839`，旧取点方法可能在元素仍移动时读到临时坐标；随后送出的鼠标输入没有送达目标章节按钮。仅检查宽度、高度和底部贴边不足以证明面板已经到达正确位置。

`scripts/browser-smoke.mjs` 本轮增加了：

- 对普通控件要求可见、不在 `inert` 内且中心点可被 `elementFromPoint` 命中。
- 取点后跨两次 `requestAnimationFrame` 比较边界框，位置或尺寸移动超过 0.5px 时重新取点；属于基于实际状态的可操作性判断，不是固定长等待。
- 阅读几何检查补充 `abs(rect.left) < 2`，保留原宽度、目标高度比例及底部对齐要求。
- 章节按钮记录真实点击诊断，并在失败时输出面板、工具栏、章节、滚动位置和 ARIA 状态。
- 切换章节后再确认唯一 `aria-current` 与 `aria-pressed` 保持一致。
- 星点输入重试前重新采集已绘制位置，并等候新帧，失败时保留尝试坐标和绘制帧号。

修正后已经取得一次完整默认 E2E 退出码 0，覆盖五个既定视口。它证明该次执行的自动化断言通过，不证明所有设备或旧失败已经完全归因；重复稳定性仍由集成者继续验证。

### 7.4 GitHub 离线检查失败的根因与修正

[首次失败日志](2026-10-24-github-pr-failure.log) 只记录“Service Worker 未接管”；[补诊断后的失败日志](2026-10-24-github-sw-diagnostic-failure.log) 明确显示应用 `ready=complete`、`loading.hidden=true`、注册 `active=activated`，但 `controller=null`。这不是数据加载失败。

[独立严格探针](2026-10-24-service-worker-probe.md) 每次要求 `performance.timeOrigin` 改变且新应用初始化完成，再读取控制器：在线硬重载两次均无控制器，普通重载两次均受控；禁用 HTTP 缓存再断网，普通重载仍从 Service Worker 恢复。探针源码随项目保存，未新增依赖。

`Page.reload({ignoreCache:true})` 可绕过已有 Worker。原测试在控制器缺失时再次硬重载，注册已经激活，不会重新触发安装期 claim；增加超时无法修复。修正只涉及测试：接管与断网使用普通重载，单独 `Network.setCacheDisabled(true)` 排除 HTTP 缓存；三次重载均用 `timeOrigin` 守卫，避免旧文档的就绪状态误通过。保留失败分项诊断，不改变产品 SW 算法、缓存版本或原业务断言。
