# 易象图谱 GitHub 发布与全面升级计划

- 日期：2026-08-06
- 状态：代码侧开发完成；生产验收与内容审校待发布前执行
- 目标版本：`v1.0.0`
- 发布方式：GitHub Pages（`web/` 静态站点）

## 1. 产品目标与执行原则

把项目从“功能丰富的本地原型”升级为可公开访问、移动端可用、内容可信、质量可持续的易经学习产品。保留原生 HTML/CSS/JavaScript、星图核心交互和墨空鎏金视觉；不做框架重写。运行时继续零依赖，开发依赖仅在能显著提高自动化质量时引入。

核心用户路径统一为：今日切入 → 星图探索 → 经文与注解学习 → 复习/测验巩固 → 黄历与占筮工具。所有传统术数内容明确标注文化学习属性，不包装为科学、医疗、法律或投资建议。

## 2. 当前基线与主要风险

### 已具备

- 64 卦、384 爻注解和情境字段完整；关系星图、卦序、复习、测验、占筮、梅花易数、黄历均已有实现。
- JavaScript 语法检查通过；卦象关系及黄历核心算法测试主体通过。
- 静态资源规模较轻，适合 GitHub Pages，无需后端。

### 发布阻断项

- `render-smoke.test.mjs` 有 5 个页面失败：旧页面模块、现用入口和测试已脱节；详情测试参数也不符合当前接口。
- `main.js` 同时承担路由、状态和多个模式 UI，旧 `*-page.js` 文件又继续存在，形成两套实现。
- 390px 移动端导航被截断，顶部栏实际宽 708px；Logo 竖排，黄历面板顶部内容和关闭入口不稳定。
- 默认激活“黄历”，进入星图后却未打开黄历面板，导航状态与页面状态不一致。
- 无 CI、Pages 部署、License、站点元数据、PWA、无障碍规范和发布检查清单。
- 当前工作区有未提交代码、临时服务器文件和多份 PDF；PDF 可能涉及版权且不应误推送。
- README 与路线图仍描述已经改变或不可达的功能。

## 3. 分阶段路线图

### M0：基线保护与发布决策（P0，0.5–1 天）

1. 备份并整理当前未提交修改，建立 `codex/release-upgrade` 分支；临时文件与参考 PDF 加入忽略规则。
2. 扫描全部 Git 历史中的密钥、隐私数据、大文件和版权资产；建立第三方字体、代码、数据与引用文本清单。
3. 先建立最小 CI：JavaScript 语法、JSON 完整性和现有单元测试；后续阶段不得在红色基线上继续叠加改动。
4. 记录功能清单、数据来源、算法适用范围和已知问题，冻结 `v0.9.0` 基线。
5. 确认公开仓库名、代码与内容许可、是否保留 `legacy-flutter/`、默认时区和是否使用自定义域名。

验收：工作区和完整历史只包含明确可发布的文件；任何 PDF、密钥、隐私数据或来源不明内容均未进入公开仓库；最小 CI 全绿。

### M1：稳定性与架构收敛（P0，2–4 天）

1. 选择单一页面架构：把模式控制器从 `main.js` 拆分，复用现有引擎；删除或接回不可达的旧页面模块。
2. 修复详情渲染的必需参数、导航激活状态、面板开关、搜索空状态和数据加载失败路径。
3. 恢复“学习”入口，统一承载十翼、象数理论、学习路径和黄历知识；同步更新信息架构。
4. 为 localStorage 数据增加版本号、异常恢复、导出/导入和清空确认。

验收：六大核心流程均可从首页到达；刷新、返回和错误数据不白屏；浏览器控制台无错误。

### M2：移动端、易用性与无障碍（P0/P1，3–5 天）

1. 建立 390/768/1280px 响应式布局：移动端导航、全屏抽屉、安全区、触控尺寸和滚动区域独立处理。
2. 为所有图标按钮添加可访问名称；导航使用 `aria-pressed`/当前状态，弹层管理焦点并支持 Esc。
3. 增加键盘操作、`:focus-visible`、Canvas 文本替代和高对比度检查。
4. 支持 `prefers-reduced-motion`；页面后台时暂停星图动画；外部字体失败时保持清晰布局。

验收：三个目标宽度无横向溢出；键盘可完成探索、详情、复习和测验；关闭入口始终可见。

### M3：测试与持续集成（P0/P1，2–3 天）

1. 将测试统一为从仓库根目录运行的单一命令，修复依赖工作目录的问题。
2. 冒烟测试只覆盖真实入口和可达模块；为复习调度、测验、占筮、梅花易数、日期边界补单元测试。
3. 使用 `node --test --experimental-test-coverage` 检查 `hexagram-utils`、关系、复习、测验、占筮、梅花易数及黄历算法模块，目标语句/分支覆盖率不低于 90%。
4. 扩展 GitHub Actions：渲染冒烟和覆盖率门槛；若获准加入 Playwright，再覆盖 1280×720 与 390×844 的主流程。

验收：CI 全绿、冒烟测试 0 失败、失败命令返回非零状态，README 中命令可直接复制执行。

### M4：内容合规与性能收口（P0/P1，2–4 天）

1. 逐项审核注解、卦辞、黄历、梅花易数和第三方字体的来源、授权和表述；补参考文献、内容说明与纠错入口。授权未定不得公开。
2. 明确黄历算法支持年份、时区和流派差异；在支持范围的起止年、闰月、春节和二十四节气中选取不少于 50 个固定样本，与两个独立可信历表交叉验证。
3. 限制 Canvas DPR、节流 resize/滚轮事件、按需初始化模式、缓存静态数据；移除永久 `no-cache` 策略。

验收：星图连续运行 60 秒时桌面平均 ≥ 50 FPS、目标移动设备平均 ≥ 30 FPS，切到后台后停止动画循环；核心内容均能追溯来源或明确标注为项目自撰。

### M5：GitHub 发布治理与站点能力（P0/P1，1–2 天）

1. 完善根 README：产品截图、在线演示、功能边界、本地运行、测试、数据隐私和路线图。
2. 添加 `LICENSE`、`CONTRIBUTING.md`、`SECURITY.md`、Issue/PR 模板；代码与内容许可证分开说明。
3. 配置分支保护、必需检查和最小 Actions 权限；Pages 部署启用环境保护、并发控制和部署产物留存。
4. 编写发布运行手册：Go/No-Go 由仓库所有者签署，记录版本、检查结果、已知风险、上一版本重部署和紧急停用 Service Worker 的步骤。
5. 配置 GitHub Pages 工作流，部署 `web/`；先发布 `v1.0.0-rc.1`，通过验收后再发布 `v1.0.0` 和 Release Notes。
6. P1 增强：favicon、Web App Manifest、受控离线缓存、`robots.txt`、`sitemap.xml`、CSP、描述、Open Graph 和分享图。

验收：无站点缓存的 Chrome/Edge 可访问，刷新子状态不报错；离线范围有明确清单；Pages 只在 CI 全绿后部署，并可按运行手册恢复上一版本。

### M6：发布后增强（P2，持续）

- ✅ 学习进度总览、连续学习天数、错题回练、分享深链接和占筮历史已于 2026-08-06 实现。
- 匿名、隐私友好的访问统计与错误监控（需单独确认）。
- 学习路径个性化、可分享学习卡片、更多卦际关系课程。
- 多语言、主题切换、可安装桌面体验；暂不建设后端账户与社区。

## 4. 发布质量门槛

- 功能：探索（含搜索与关系详情）、学习、复习、测验、占筮、黄历六条路径均完成端到端验收。
- 缺陷：P0 定义为数据/版权/安全风险或核心路径完全阻断，P1 为核心路径可绕过但明显受损；公开发布时 P0/P1 均为 0。
- 测试：所有自动化检查通过；核心逻辑覆盖率 ≥ 90%。
- 体验：自动化覆盖 Chromium 1280×720、390×844；人工覆盖 Chrome/Edge 桌面和至少一台 Android Chrome、一台 iOS Safari。各尺寸无溢出，触控、键盘和减少动效模式通过。
- 性能：在 Pages 生产 URL、Chrome 稳定版、Lighthouse 移动端默认节流下连续运行 3 次取中位数；Performance ≥ 80，Accessibility/Best Practices/SEO ≥ 90，LCP < 2.5s、CLS < 0.1。
- 内容：版权、来源、免责声明和算法边界已审查。
- 仓库：无大体积参考 PDF、密钥、临时文件或无关历史产物。
- 发布：仓库所有者完成 Go/No-Go 清单；RC 通过上述设备矩阵，版本标签、部署产物和回滚演练均可用。

## 5. 待确认决策与推荐默认值

| 决策 | 推荐默认值 |
|---|---|
| 仓库可见性 | 公开仓库 |
| 部署 | GitHub Pages，首版不绑定自定义域名 |
| 许可 | 代码采用 MIT；内容按来源文档单独审校 |
| 参考 PDF | 本地保留、Git 忽略、绝不发布 |
| Flutter 旧版 | 创建归档标签后从主分支移除 |
| 时区 | 黄历默认 `Asia/Shanghai`，界面明确显示 |
| 技术栈 | 运行时零依赖；测试工具按需引入开发依赖 |

## 6. 建议执行顺序

先完成 M0–M3，形成内部预览版 `v0.9.0-preview.1`；完成 M4 的合规门槛和 M5 的发布治理后形成 `v1.0.0-rc.1`，通过质量门槛再公开发布。每个里程碑拆成 GitHub Issues，标签使用 `P0-release`、`P1-quality`、`P2-growth`，每次合并都附实际测试结果和界面截图。
