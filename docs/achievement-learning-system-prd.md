# Product Requirements Document: 修习成长与荣誉体系

**Version**: 1.0
**Date**: 2026-08-14
**Quality Score**: 92/100

## Executive Summary

“修习成长与荣誉体系”把现有的五阶课程、小试、错题、间隔复习、星图探索和占筮案例串成持续成长循环。它服务于初学者最常见的困难：知识难记、学习缺少反馈、看完经文后不知道自己是否真正理解。

系统采用“雅致书院 70% + 游戏反馈 30%”的克制游戏化。核心知识始终开放；成就只奖励真实学习证据、解释能力和长期复习，不奖励重复点击、连续起卦或不可验证的预测结果。

## Goals and Success Criteria

- 让用户始终知道“已经学会什么、下一步做什么、为什么获得奖励”。
- 将解卦从结果展示升级为“识卦—取象—引经—推演—反思”的可解释练习。
- 12 枚首发成就必须在自动化测试夹具中全部可达成，且条件可追溯。
- 同一行为重复提交不得刷取修习值；断网、本地存储失败和旧数据升级均有明确降级。
- 成就计算在普通桌面浏览器中应低于 100ms，不引入运行时依赖或后端要求。

## Product Principles

1. **学业先于奖励**：掌握度反映学习质量，修习值只表达历程与荣誉。
2. **过程先于吉凶**：解卦评价推理证据，不判断预测是否“应验”。
3. **公开且可解释**：所有成就展示条件、进度、达成依据和下一步建议。
4. **不锁核心内容**：奖励只解锁称号、印章、星图表现、分享样式和可选声景。
5. **数据默认本地**：不保存敏感问题原文；自由文本仅在用户明确保存时进入“观象录”。
6. **无惩罚式连续学习**：中断学习不会清零长期成果，也不制造焦虑。

## Core User Journey

```text
学习课程 → 小试/抽查 → 间隔复习 → 自主解卦 → 五维反馈
    ↑                                              ↓
推荐薄弱项 ← 能力图谱 ← 修习值/铜印/称号 ← 达成依据
```

### Learning Ranks

沿用“蒙学、习经、研传、明辨、通用”五阶，每阶包含“初识、渐悟、成章”三个成长状态。晋阶必须同时满足课程掌握度和关键实践条件，不能只靠累计修习值。

### Ability Dimensions

- **识象**：卦象、上下卦、卦序和结构辨认。
- **读经**：卦爻辞、《易传》与出处理解。
- **观变**：动爻、本卦、之卦与错综互变。
- **明辨**：区分事实、类比、推断及其适用边界。
- **表达**：用自己的话形成连贯、有依据的说明。

## Divination Interpretation Challenge

起卦后提供“自主解卦”和“直接研读”两条路径。直接研读保留学习记录但不计挑战成绩；自主解卦依次完成：

1. 识别本卦、之卦和动爻。
2. 选择卦象表达的核心处境。
3. 选择或引用匹配的卦爻辞、象传或系辞依据。
4. 说明从经文到现实参照的推演过程。
5. 明确反思问题与现实决策边界。

评分为识卦、取象、引经、推演、边界各 20 分。结果分为“初观（0–39）、得象（40–59）、有据（60–74）、明辨（75–89）、通达（90–100）”。本地模式优先评价结构化客观项；自由文本采用透明自评清单，可选安全服务端评阅，不在浏览器或仓库存放模型密钥。

## Technical Contract

统一进度事件格式：

```js
{
  type: 'lesson.assessed',
  subjectId: 'l1-1',
  score: 0.9,
  outcome: 'passed',
  occurredAt: '2026-08-14T10:00:00.000Z',
  idempotencyKey: 'lesson.assessed:l1-1:2026-08-14',
  metadata: { source: 'section-check' }
}
```

事件只保存成就计算所需的最小字段。核心类型包括 `lesson.completed`、`lesson.assessed`、`review.completed`、`quiz.recovered`、`hexagram.read`、`relation.examined`、`divination.analysis.submitted`、`divination.analysis.revised` 和 `boundary.acknowledged`。

本地状态使用版本化键 `yijing.achievements.v1`。引擎必须提供数据校验、幂等处理、旧状态迁移、事件聚合、成就判定、能力汇总和导入导出接口。UI 不直接修改状态，只通过事件接口写入。

## MVP Scope

### Included

- 12 枚成就、五维能力图谱、15 个学阶小状态。
- 解卦五步挑战、透明评分、修改后再提交。
- 学习、测验、复习、星图阅读的统一事件接入。
- 学习模块内的“修习谱”、全局轻量达成提示和成就分享数据。
- 本地持久化、备份导入导出、无障碍与减少动态效果。

### Excluded

- 账号、排行榜、社交对战、付费商城、抽卡、每日体力和核心知识锁定。
- 将占筮结论描述为确定预测，或按现实事件是否发生判定正确。
- 默认上传用户问题、解卦文本或行为分析数据。

## Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| 自由文本评分显得武断 | 高 | 客观项与主观项分开；显示评分依据；允许修改与人工自评 |
| 游戏化损害文化气质 | 高 | 使用修习谱、铜印、学阶和金石声景；禁用金币、宝箱与礼花 |
| 重复操作刷奖励 | 中 | 事件幂等键、唯一主题计数、每日上限和首次有效行为原则 |
| 多窗口并行修改冲突 | 高 | 独立 worktree/分支、严格文件所有权、最后由单一集成窗口改入口文件 |
| 本地数据升级丢失 | 高 | 版本化 schema、迁移测试、损坏数据降级与导出兼容测试 |

## Release Gate

- 全部新增纯逻辑模块达到项目 90% 行/分支/函数覆盖门槛。
- `npm test`、`npm run test:coverage`、`npm run validate` 全部通过。
- 1280×720 与 1440×1024 验证修习谱、解卦挑战和达成反馈首屏可用。
- 键盘可完成完整挑战；成就弹层不抢占或遗失焦点；减少动态效果有效。
- 典籍引用来自现有数据或经校验的来源说明，不使用生成图片中的文字。
